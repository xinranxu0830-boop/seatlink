# SeatLink · 学校样式与偏好找座

发布分支 `compact-preferences-ui`。参考组员 V3 推荐规则，外观沿用学校预约系统的蓝色标题栏、浅蓝区域栏和黄绿座位图。**[在线演示](https://xinranxu0830-boop.github.io/seatlink/)从本分支根目录发布；`main` 保留原基础版。**

## 本地运行

```sh
npm ci
npm run dev -- --port 5175
```

打开 http://127.0.0.1:5175/ 。`npm run build` 输出到 `dist/`，资源使用相对路径，兼容 GitHub Pages 的 `/seatlink/`。

GitHub 分支根目录保存可直接静态托管的构建产物；`source/` 保存本项目源文件。克隆该分支后先 `cd source` 再运行以上命令。根目录与 `source/README.md` 分别说明发布结构和开发方式。

## 操作

- 默认进入 C200 座位图。顶部改日期／时间；工具栏 **⋯** 展开偏好图标。选中“必须满足”后，不符合或未知都排除。
- 列表／地图切换；“整段”可切换为“含短时”；点击座位查看、备注并预约。
- 底部 **智能找座** 进入原时间规划算法；**预约管理** 查看、取消、续座。
- **首页** 恢复场馆列表，C200 中区可进入；其他区域未开放。**个人中心** 可进入模拟控制和数据说明。
- 右上播放图标打开四个合成场景和东区预约回放。合成场景使用独立数据。
- 右上控制图标推进模拟时间或模拟入馆／离馆；“模拟”标记可查看数据说明。

图标带可访问名称与悬停说明，弹层支持 Escape、点击外部关闭和焦点回到入口。手机使用底部详情弹层。颜色之外保留时段、图案、未知问号和状态文字。

## 推荐逻辑与模拟数据

先满足时段，再按偏好匹配数排序；未知不算符合。“必须满足”会同时排除不符合和未知。列表、地图同源，预约提交时重新验证实际时段。

显示屏、HDMI、采光、直晒时段、隔板、通道、空调和附近人数均为**合成演示数据**。完整字段、数量、生成方式和有效期见 [模拟说明](docs/simulated-preferences.md)。东区预约回放内置由真实预约表生成的独立脱敏汇总，不影响中区地图与普通预约的演示数据。

偏好只作用于单座推荐；拼座／续座继续按时间安排，不考虑环境偏好。续座需主动查找或按演示步骤触发，未实现后台监测和推送。

## 预约规则与状态

- 08:00–22:30；22:30 起默认次日，之前默认当天。
- 每段 60–960 分钟，且不能超出当日开馆时间。
- 用户批准的实验规则：可保留多条预约，个人时段不能重叠。
- 入馆即签到，超时 30 分钟释放；离馆释放当天未结束预约。
- 每段默认至少 60 分钟、最多换一次、空窗默认最多 5 分钟；有空窗要单独确认。不额外扣搬东西时间。
- 固定初始时间为 2026-11-19 12:43，不随真实时钟自动推进。
- 83 座中仅 2 个编号位置已核对，其余是临时 SIM 编号。

普通预约继续使用 `c200-reservation-simulator-v2`，演示使用 `c200-guided-demo-v1`，偏好使用独立键 `seatlink-compact-preferences-v3`。每个浏览器各自保存，不是多人服务。

## C200 东区预约回放

在 `source/` 中运行以下命令。原始预约表默认位于 Git 仓库旁的 `data/`，也可在第一条命令后加 `-- <预约表路径>`。需要本机 Python 3 和 `openpyxl`。环境变量 `SEATLINK_PYTHON` 可指定 Python 路径。

```sh
npm run experiment:c200
npm run dev -- --port 5175
```

打开「场景演示」中的「东区真实预约回放」，默认显示 2026-10-29 的 317 条预约、108 个记录内座位的四组回放。可切换「真实记录」与「模拟加量」（+25%，向上取整为 80 条）、拖动分时进度，并查看座位用字母标记的单请求示例。真实负载下四组预约利用率均为 58.637%，不据此宣称存在提升。

开发服务可在本机读取 `.qa/c200-replay.json`；线上页面默认使用 `src/c200-replay.public.json`，也保留「导入其他汇总」。更新内置汇总时，先运行 `npm run experiment:c200 -- <预约表路径>`，再运行 `npm run experiment:c200:publish` 和 `npm run build`。公开汇总生成器只保留明确允许的统计字段和字母座位示例，原始 Excel、读者标识和逐条预约表保留在本机。

该表有 14 条记录在预约开始前或开始时已结束，38 条真实结束时间晚于预约结束（计算时截至预约结束），24 条提交早于 Demo 的次日预约开放窗口。沿用学长的历史回放口径，不改写原始时间；这一天仅包含成功预约记录，不能代表全部未满足需求。分母仅包含表中出现的 108 个座位，分配时长不代表实测在座时长。

四组共享按提交时间排序的请求和座位池。排程使用现有 `planSeats`、`planRenewal` 和 `bookPlan`。本实验使用预约记录中出现的东区座位，记录的结束时间只在回放到达对应时点后释放余量。利用率衡量预约时段，以实际结束时间裁剪后的分配秒数为分子，座位数乘开馆秒数为分母。

两份审阅 PDF 的生成脚本使用 Windows 等线字体和 `reportlab`。原始回放报告可用 `python scripts/build-c200-report.py` 从本地汇总生成。

### 当前压测按时段密度随机加量

```sh
npm run experiment:c200:density
python scripts/build-c200-density-report.py
```

在 +50% 和 +100% 两档比较 11 种策略。首段下限为 45 或 60 分钟，后续段至少 60 分钟。新增条数按有效预约开始时刻的半小时占比分配，用最大余数补齐总数。开始时刻在时段内随机选择，提交提前量和释放比例从同一时段的原记录分别抽取。期望学习时长参考原记录，将超过 60 分钟下限的占比换算到新的开馆窗口，在换算值前后 10 分钟内抽取满足时长边界的整分钟。每档使用种子 1 至 10，同一种子下各策略共用请求。

回放输出 `.qa/c200-density-pressure-45min.json`。审阅稿在工作区的 `output/pdf/` 中生成，首页并列展示 60 分钟单座、仅拼接、仅续座及拼接与续座同时开启的结果，并给出 45 分钟单座兜底的配对差。

### 历史策略改进试验

```sh
npm run experiment:c200:improve
```

命令依次对比首段 60、45、30 分钟、60 分钟候补、提前锁定与提前 15 分钟逐段确认，以及晚间加量场景。首段下限只影响首段，后续预约仍至少 60 分钟。候补最多接受晚于目标时间 30 分钟开始，测试释放即重试和到目标时刻后才重试两种做法。逐段确认用同一规划器计算方案，每次仅锁一段，在尾段结束前 15 分钟开始查下一段。晚间加量保留原预约，另加 40 或 80 条集中在 18:00 至 20:30、目标时长 120 至 180 分钟的模拟请求。

结果写入本地 `.qa/c200-improvements.json`。首约失败按提交时未能分配首段计数，候补命中另计。完整覆盖要求从目标开始到有效结束都有座位。高峰请求按目标开始落在 18:00 至 22:00 筛选，分时预约利用率按同一时段的座位容量计算。

如已取得同一天的匿名预约意向，可用 `npm run experiment:c200:improve -- --demand <意向文件.json>` 增加一组回放。记录原本想约的时刻和最终结果，补充文件只收最终未约成且未进入预约原表的意向。每条意向按原期望结束时刻建模。保存于仓库外，字段使用下例的格式。

```json
{
  "date": "2026-10-29",
  "requests": [
    {
      "submittedAt": "2026-10-29T17:30:00+08:00",
      "desiredStart": "2026-10-29T18:00:00+08:00",
      "desiredEnd": "2026-10-29T19:30:00+08:00",
      "outcome": "unfulfilled"
    }
  ]
}
```

### 闸机联查与临时补位

```sh
python scripts/run-c200-gate-replay.py
```

默认读取仓库旁 `data/` 中同一天的东区预约表和主馆闸机表。程序在内存里按读者键匹配，只向 `.qa/c200-gate-replay.json` 写汇总。可用 `--bookings` 和 `--gate` 指定输入文件。

保留窗口从预约开始算起，到入馆、记录释放、闸机状态无法判定或 30 分钟期限的最早时点为止。回放同时保留只使用已有出馆记录的口径。改约候选要求原预约提前结束后 90 分钟内提交更晚开始的有效预约。结合同一读者的闸机时间，可标记与迟到改约一致的候选。

两组均优先分配普通空座。补位组才使用保留中的短窗口，闸机入馆事件截断临时使用。分配时用当时可见的计划截止时间选择座位。每次短用扣除 2 分钟准备时间，计划至少可用 5 分钟才接受。真实日志的需求代理取预约前已经到馆、临近开始且没有重叠东区预约的读者。另测 18:00 至 22:00 每 5 分钟新增 4 或 8 条、各想坐 15 分钟的模拟压力。闸机记录用于推断预约人是否在馆，椅子是否实际空着和现场交接耗时需用座位观测确认。

### 历史压测采用同型请求加量

```sh
npm run experiment:c200:stress
python scripts/run-c200-gate-replay.py --heavy-pressure
```

预约回放按原表总行数向上取整，分别加 159 条和 317 条。同型模拟请求来自按提交顺序等距抽取的有效预约，沿用提交、目标时段和释放时间，使用独立模拟读者键。同一负载下各策略共用请求。短坐回放保留实录代理和原预约，以每 5 分钟 8 条模拟短坐为基线，测 12 条和 16 条。汇总分别存为 `.qa/c200-heavy-pressure.json` 和 `.qa/c200-gate-heavy-pressure.json`。
